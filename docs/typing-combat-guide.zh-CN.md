# 打字战斗实验：完整易读版

版本 **0.1**，2026 年 10 月 9 日。当前状态：**供后续制作与试玩使用的设计案，尚未实现，也尚未经过玩家测试。**

这份说明与 [英文实现规格](typing-combat-spec.md) 是同一份设计的两种表达。这里用日常语言解释规则，但保留所有重要数值、特殊情况、验收项目和判断标准。D01–D18 编号一一对应，方便讨论和同步修改。现有 `Validation` 场景是另一个原型；它之前通过的测试不能算作本设计的验证结果。

先用一句话理解要做什么：**玩家在敌人的预警与攻击之间寻找空档，输入一小段咒语；最后一个字母打对，技能立刻命中。打错或受击会退回部分进度，但已经完成的单词会保留。**

阅读路线：D01–D03 说明目标与流程；D04–D12 写清“按什么、会发生什么”；D13–D16 说明怎样验证功能与体验；D17–D18 说明制作顺序和证据边界。实现与日志细节也保留在本文，不需要为了了解重要规则再读另一份文件。

## D01 — 这次到底要验证什么

核心问题是：**玩家一边读短句、输入字母，一边应对看得见的威胁，能否做出容易理解、令人满意的战斗选择？**

完整体验应当包含：发现危险 → 决定开始或继续输入 → 输入字母 → 从打错或受击中恢复 → 完成咒语并立即攻击 → 再次判断局势。只有打字准确率高，不能说明战斗有趣；程序测试通过、外观像参考游戏，也不能证明它好玩。

后续要制作的是一个独立的 Windows 键盘实验场景，包含一个敌人、一个技能、练习、两种可比较的时间模式、结果画面、本地记录和验收测试。角色沿平地左右移动，保留项目的侧视特点。这里不需要跳跃或平台跳跃挑战。

本轮暂不加入：格挡攒能量、普通近战、多技能选择、物品栏、捡书、解谜、掉落物、剧情推进、正式美术、随机生成内容、咒语翻译、手柄、联网或云端统计。这是为了单独验证打字交互，不代表取消完整游戏中的这些功能。角色反馈、危险提示和攻击反馈必须保留，因为它们会直接改变体验。

本文没有通过购买、安装或亲自游玩《The Textorcist》取得证据，研究依据是公开资料。下面的数值都是 **Keyboard Warrior 本次实验的设计选择**，不是从参考游戏提取的参数，也不是已经验证的平衡结果。

## D03 — 一局怎么进行，两种模式怎么比较

流程固定为：**设置 → 练习 → 准备画面 → 3 秒倒数 → 战斗 → 结果**。结果画面选择重试，会以相同实验条件返回准备画面。只能在战斗外更改模式或辅助设置；改变后要建立新的局次记录。

开局时角色在 x=0，生命 3；敌人生命 100；还没有激活咒语，也不沿用上一画面一直按住的按键。敌人的实际运行时间经过 2 秒后，开始第一次预警。

按一次 **1** 开始这次咒语。短句一旦出现，在本次尝试中保持不变。打对最后一个字母便自动造成 **25 点伤害**，然后冷却 **0.60 秒**；冷却完必须重新按一次 1，才开始下次。成功释放 4 次击败敌人；受到 3 次有效伤害则失败。累计有效战斗时间达到 **120 秒**，结果是 `TimeLimit`（时间到，未完成），不算死亡。

| 模式 | 正在输入咒语时 | 用途 |
| --- | --- | --- |
| `RT`，实时模式，主要方案 | 敌人继续行动，角色仍可移动；停止打字不会让战斗停止。 | 验证时机选择、注意力分配和同时操作。 |
| `PAUSED`，输入时暂停战斗，比较方案 | 整个咒语输入阶段都冻结敌人阶段、伤害检查和角色位置；文字仍可输入。 | 观察输入时暂停战斗产生的差异。此模式冻结移动也是规则的一部分。 |

两种模式使用相同短句、伤害、输入规则和敌人参数。只有输入阶段的战斗推进规则不同；不能偷偷换成更慢的敌人、更简单的词或不同的输错惩罚。输入之外，两种模式都正常推进战斗。

两种模式都**没有单句倒计时**。一局的 120 秒时限在输入时仍然前进。`PAUSED` 的敌人实际运行时间较少是预期现象，分析时必须单独记录，不能直接把它较少受击归因于操作更好（见 D14）。

练习明确分三步。每步都显示 `PRACTICE`，沿用同样的输入/暂停/反馈规则，以 3 秒倒数开始，**不设 120 秒时限**。经过时间和事件都标为练习，不计入正式测量。正式测量中没有隐藏的自动难度调整。

| 练习阶段 | 哪些规则运作 | 怎样往下走 |
| --- | --- | --- |
| 只打字 | 每次成功后重复 P0；角色位置固定，无敌人攻击；技能/冷却正常。木桩从 100 生命开始，伤害将使它归零时立即重置到 100，不产生胜利。角色保持 3 生命。 | 玩家或引导者选择“下一步”才继续。 |
| 只躲避 | RT 移动与同样的预警/攻击周期；禁止技能开始与全部字母，不显示激活短句。受击有反馈、增加练习受击统计并获得正常无敌，但不扣显示的训练生命。 | 选择“下一步”才继续。 |
| RT 综合 | 重复 P0，使用完整 RT 规则，包括角色 3 生命、受击重置单词与锁定；木桩仍自动恢复，不产生胜利。角色死亡进入练习结果画面，Enter 可干净地重开本步。 | “下一步”结束练习并打开正式准备画面，练习状态不带入正式局。 |

每步按 Escape 暂停，菜单有继续、重开本步、下一步、返回设置、退出。↑/↓ 与 Enter 选择；练习结果画面也提供这些操作，但没有“继续”，默认选中“重开”。重开仍在相同步骤；未达到建议练习时长也能选下一步。D15 的教学时长由引导者掌握，不是自动倒计时。练习记录含 `practiceStage`；重置创建新局 ID，但不算正式测量中的失败惩罚。

## D04 — 键盘操作与哪些输入有效

| 按键或输入 | 战斗中的具体结果 |
| --- | --- |
| 按住 ← / → | 左右移动；实时模式输入或受击反应期间也能移动。两个方向同时按住，移动速度为 0。 |
| 主键盘 1 或数字小键盘 1，重新按下 | 仅在技能就绪时开始咒语。输入中、受击锁定、冷却和已结束时都忽略。 |
| 真实按键产生的 A–Z / a–z | 输入阶段且未受击锁定时参与匹配，不分大小写。A/D/J/K/E/R 等都只负责字母输入，不触发旧原型的战斗动作。 |
| 空格、标点，以及不作为开始命令的数字 | 不增加或减少进度，也不算输错；记录为“忽略的输入”。它们不会被偷偷插入短句。 |
| Backspace / Delete | 不编辑、不主动后退。这是游戏进度，不是文本编辑框。 |
| Enter | 战斗中不提交。菜单中确认选项；结果画面先松开旧按键，再按 Enter 才能重试。 |
| Escape | 暂停；已经手动暂停时申请恢复。它不会取消当前咒语。 |
| ↑ / ↓ | 战斗外选择菜单；战斗中没有作用。 |
| Shift / Caps Lock | 不改变字母身份。v0.1 中 Shift 不用于切换移动。 |
| Ctrl / Alt / Windows 组合快捷键、Tab、功能键 | 不输入字母，也不触发技能。系统快捷键照常由系统处理；切离窗口会按 D06 暂停。 |

基准环境是 **Windows + 英语美式键盘/输入布局**。匹配的是按键实际产生的拉丁字母，不是假定所有布局中物理键名都相同。其他布局、输入法组合、死键组合和非拉丁文字在 v0.1 尚未验证。不支持的字符不推进进度、不算输错；用限制频率的提示告知切换英语输入，不把未知 Unicode 字符近似转换成英文字母。界面可以中文或英文，实验短句不变。

不读取剪贴板，不接受粘贴、自动补全、语音输入，也不把系统长按重复当成多次输入。**按住一个字母只算一次；要输入连续两个相同字母，必须松开再按。**按住 1 也不能连续开始技能。

输入处理必须分清“按键产生的文字”和“真实的一次按下”，关联两者并保留快速连续按键。仅接上 Unity 的 `onTextInput` 事件并不能证明已正确过滤长按、粘贴和来源；制作第一步必须专门验证（D17）。不支持的组合输入或一次提交多个字符要拒绝；但多个普通按键恰好在同一画面帧到达，必须按顺序分别处理。

所有游戏输入进入同一个有顺序的队列，不能让一个 UI 文本框另外改变游戏。移动和打字允许同时发生。菜单用过的确认键要被消耗，待处理的游戏输入要清空，并且松开后才能再次生效。进入战斗后，若同一次输入更新中先按了 1、随后真正按下首字母，首字母有效；不能仅因它们落在同一个画面帧而丢掉首字母。

## D05 — 咒语、保存进度与输错规则

短句是固定数据，每条记录包含 ID、版本、显示文本和单词列表，即 `{id, version, displayText, words[]}`。初始词库版本为 `prompts-v0.1`，每条短句的整数版本均为 `version: 1`。只允许小写 ASCII 英文字母，单词之间恰好一个空格，句首句尾无空格，也无标点。空词、非字母、重复 ID，或单词拼起来与显示文本不同，都属于无效数据。正式测量中不得临时生成或用 AI 生成短句。

| 词库 | ID | 屏幕短句 | 实际需要输入的字母数 |
| --- | --- | --- | --- |
| 练习 | P0 | `burn the seal` | 11 |
| A | A1 | `break the seal` | 12 |
| A | A2 | `light the path` | 12 |
| A | A3 | `guard the gate` | 12 |
| B | B1 | `break the lock` | 12 |
| B | B2 | `light the hall` | 12 |
| B | B3 | `guard the wall` | 12 |

这些是实验原创的短句，占位供以后剧情写作调整。A/B 库每句的单词长度均为 5/3/4，只证明长度匹配，不证明词汇熟悉度或手指运动难度相等。

每局按该词库的 1、2、3、1 顺序，完成四次技能。开始一次尝试时取当前词条；只有成功释放才推进词库位置。受击、输错不换句。重试回到词库第 1 条。

游戏只需记住两个位置：当前是第几个单词、该词已经正确输入几个字母，程序中为从 0 开始计数的 `wordIndex` 和 `letterIndex`。规则如下：

- 正确字母：当前词的字母进度增加 1。
- 完成一个非最后单词：立即保存这个词，转到下个词，字母进度归 0。**不用按空格或确认。**
- 完成最后一个词：产生一次完成事件并立即攻击（D09）。
- 打错一个可识别的英文字母：只撤销当前词中最后一个已正确输入的字母，最低退到 0；不会撤销已完成的词。错字只消耗一次，退回后不能重新把同一个错字再匹配一次。
- 输错不扣生命，不锁输入，不额外收费，不换句。提示新的应输入字母。之后的每次真实按键都按新位置判断，即使玩家本来想继续打旧的后半段。

用练习句 `burn the seal` 看完整例子：

| 操作 | 结果 |
| --- | --- |
| 开始后输入 B、U | 当前词 `burn`，已完成 `bu`，下一字母是 `r`。 |
| 接着输入 X | 退成 `b`，下一字母是 `u`；X 不会再被处理第二次。 |
| 再输入 U、R、N | `burn` 保存；进入 `the`，当前词尚未输入任何字母。 |
| 在 `the` 开头输入 X | 仍在 `the` 开头；已经完成的 `burn` 保留。 |
| 按空格或 Backspace | 不改变进度。 |
| 依次输入 `the`、`seal` | 最后的 L 立即触发技能，不需要 Enter。 |
| 已完成 `burn`，刚输入 `the` 的 t 时受击 | `burn` 保留；`the` 回到开头，同时进入受击输入锁定。 |

停手、移动、观察危险或暂停都保留进度，没有自然衰减。有效受击会清空当前词的部分进度（D08），已完成词保留。本实验没有掉书或捡书。

## D06 — 状态、计时与暂停恢复

要分开记录“整局处于什么阶段”和“技能处于什么阶段”：整局有倒数、进行中、暂停、结果；技能有就绪、输入中、冷却，另有受击锁定和无敌计时。不能把“输入中”统一当成“战斗关闭”，因为实时模式必须继续战斗。

| 发生的事 | 文字/技能进度 | 生命、敌人和时间 |
| --- | --- | --- |
| 移动或停止打字 | 保留 | RT 继续战斗；PAUSED 只在输入阶段冻结战斗。 |
| 输错字母 | 当前词的字母进度退 1，最低为 0 | 其他时间照常前进。 |
| 有效受击 | 清空当前词的部分进度；技能阶段不变 | 生命减 1；输入/开始锁定 0.35 秒；获得 1 秒无敌。 |
| 手动暂停、窗口失焦或键盘断开 | 保留；丢弃排队中的游戏输入 | 所有游戏计时和移动停止。 |
| 恢复 | 保留；不重放旧输入 | 满足松键与确认要求，倒数 1 秒，再从保存的敌人阶段继续。 |
| 技能成功 | 结束本次尝试，进入冷却 | 敌人只减少一次 25 点生命。 |
| 获胜、死亡、时间到或退出本局 | 不再接受输入和攻击 | 结果固定，清除威胁与待处理事件。 |
| 重试 | 清空，技能回到就绪 | 双方生命、位置、词库位置、敌人阶段、计时器、输入队列和本局统计全部重置；建立新局 ID。 |

这里有几种不同的“时间”，不能混用：

| 名称 | 怎样前进 | 用在哪里 |
| --- | --- | --- |
| 现实经过时间 `wallSeconds` | 单调递增，包含暂停；系统时钟校正不能使它倒退。 | 排查问题，不用于造成伤害。 |
| 有效战斗时间 `encounterSeconds` | 包含输入、冷却、受击反应；不含开局/恢复倒数和明确暂停。 | 到 120 秒结束；反应锁定与冷却也用它。 |
| 敌人运行时间 `enemySeconds` | 只有战斗实际推进才前进。RT 与有效战斗时间相等；PAUSED 不含输入阶段。 | 敌人阶段、无敌时间、角色移动。 |
| 受击锁定/冷却计时 | 随有效战斗时间前进，明确暂停时停止。 | 即使与 PAUSED 输入重叠也能结束，不会永久锁住。 |
| UI 提示计时 | 明确暂停时保留剩余时长；PAUSED 输入时仍前进。 | 各种提示持续时长。倒数另用窗口有焦点且键盘已连接时的时间。 |

**切回窗口不会自动继续游戏。**窗口失去焦点、键盘拔出，或一次模拟间隔超过 250 毫秒，都应暂停并说明原因。恢复必须依次满足：窗口有焦点、键盘已连接、原先按住的游戏键已松开，再重新按 Enter/Escape 确认，最后倒数 1 秒。确认键不会进入咒语。

如果原本是手动暂停，重新获得焦点不能把它取消。任何倒数期间都不接受字母、移动、伤害和技能开始。倒数被打断时记住它的类型：重新确认后，开局倒数必须完整重来 **3 秒**，恢复倒数则完整重来 **1 秒**，不能缩短准备时间。进入战斗时仍然按住的游戏键，包括倒数期间新按下的键，都保持无效，必须松开再按，不能自动移动、输入或施法。菜单、暂停、确认也只认新按下，不认长按重复。

暂停菜单有：继续、重开本局、返回设置、退出程序。↑/↓ 选择，Enter 确认；Escape 只有在恢复条件满足时才申请继续。重开会把旧局记作 `Aborted`（主动中止），经过准备画面再创建新局；返回设置也记作 `Aborted`。战斗中没有字母键重开。通过系统关闭窗口要安全结束进程；若记录中已有开局而没有结束，下次分析时归为 `Interrupted`（意外中断），不能当作输或赢。

## D07 — 同时发生几件事，先算哪件

游戏逻辑固定每秒运行 **60 次**，每次称为一个“逻辑步”或 tick。每个输入带单调时间戳和序号。先从时间戳中扣除倒数/明确暂停时段，得到有效战斗时间 `t`；这些时段内发生的游戏输入直接丢弃。输入所属步骤为 `max(1, ceil(t × 60))`，即第 n 步处理 `((n-1)/60, n/60]` 内的事件，恰好在开局 0 秒的事件算第 1 步。同类事件按时间戳、再按序号处理；边界用整数步数判断，避免浮点数相等比较的误差。

移动也根据队列中的按下/松开事件，不能直接读最新画面帧的键盘状态。按顺序处理截至本步的移动事件，保存最后的按住状态，再移动一次 `方向 × 5/60` 单位；同一步先按下再松开，则以最后“已松开”状态计算。这是明确定义的 60 Hz 移动精度。画面可以是 30/60/120 FPS，但不能因此改变速度、句子长度或输入是否正确。正常延迟通过固定步骤追赶；超过 250 毫秒的间隔则暂停并标记性能问题，不在玩家看不见的时间里快速补算攻击。

每一步严格按下面顺序：

1. **先处理暂停。**失焦、设备/性能问题或明确暂停命令优先；冻结本步，丢弃本步游戏输入，保留已有状态。
2. **在改变玩法状态前，检查本步将到达的时间。**如果达到或超过 120 秒（第 7200 步），把时间设为 120，记 `TimeLimit`，本步移动、伤害、文字全部不处理。因此从 119 又 59/60 秒到达 120 秒的这一步，不能再接受最后一个字母来抢救。已结束状态拒绝任何游戏事件。
3. 推进允许前进的计时器，结束已到期的锁定/冷却；如果战斗正在推进，处理移动并限制在场地内。
4. 推进敌人阶段，检查本步是否受击，先处理伤害和死亡。**受击与最后一个字母在同一步时，受击优先。**本步发生受击就拒绝该步字母，不能靠计时边界绕过。
5. 按时间戳和序号处理技能开始与字母。合法开始事件可以先于同一步的字母；受击锁定、非输入阶段或已结束时忽略字母。完成短句与扣敌人生命一起完成，不能只做一半；敌人生命为 0，立即获胜。
6. 最后发布一份只读的画面状态和统计事件。画面绘制本身不能增加输入进度或造成伤害。

敌人一个周期内的区间是“包含起点、不包含终点”：预警 `[0, 0.90)` 秒；攻击 `[0.90, 1.05)`；恢复 `[1.05, 3.50)`。攻击期每个逻辑步都用**移动后的**受击框检查，直到这次攻击已造成一次伤害或攻击结束。一条攻击 ID 最多造成一次伤害。同时间戳的输入按已记录的序号排序；暂停仍有更高优先级。

每次完成事件包含 `{runId, attemptId, castId, tick}`，对应本局、这次尝试、这次施法和发生步骤。无论回调重复几次，同一施法 ID 最多扣一次敌人生命。完成后立即冷却，丢弃这次尝试剩余的文字事件，不能把它们送进下一句。冷却/受击锁定时的开始命令不预存；按住 1 不能在锁定结束后自动生效。菜单、重载、重试、失焦改变有效事件范围，旧局/旧尝试的排队事件一律失效。

## D08 — 最小战场与敌人的攻击

用固定侧视正交相机和一条平地。没有滚屏、跳跃、重力挑战、掩体或碰到敌人身体就受伤。平地的逻辑范围是 x ∈ [-6, 6]。角色受击框半宽 0.25，所以角色中心只能处于 [-5.75, 5.75]；移动速度 **5 单位/秒**，立即转向，没有加速过程。朝向只是外观，角色固定高度、相机构图和装饰深度不能改变碰撞。

一个静止且可见的敌人在平地右上方，建议美术位置 x=5、y=2.5；位置不限制目标选择或角色移动。敌人释放落在平地上的**竖向攻击带**，不做移动弹丸。它是为了制造注意力压力而简化的敌人，不是在决定完整游戏最终的弹幕或相机方案。

每次预警开始，记下角色当时的横坐标，作为攻击带中心 `strikeCenter`，之后不跟踪玩家。

| 阶段 | 时长 | 玩家看到什么 |
| --- | --- | --- |
| 预警 | 0.90 秒 | 宽 1.6 单位的区域，以及倒数或填充提示。 |
| 攻击 | 0.15 秒 | 同一区域真正产生伤害。 |
| 恢复 | 2.45 秒 | 本次攻击结束，等待下次预警。 |

开局 2 秒宽限后，每次周期共 **3.50 秒**，新周期重新记录玩家位置。PAUSED 输入时，这个阶段及已记录的中心都完全冻结。

判定条件为 `abs(playerX - strikeCenter) <= 0.25 + 0.80`。换句话说，中心距离 ≤ **1.05 单位**便算重叠，恰好碰边也会命中。显示的警示带必须对应同一区域；调试模式显示真实角色受击框。

若角色恰在预警中心，需要移动**超过** 1.05 单位才能避开；以 5 单位/秒移动需要略多于 0.21 秒，小于预设 0.90 秒预警。它只说明几何上来得及，不能证明人能舒适地边读边躲。场地两边都必须留有向内逃离的路线，并实际验证两个边缘。

有效受击扣 1 生命，最低为 0；清空当前词的部分进度，已完成词保留；锁定字母输入和技能开始 **0.35 秒**；获得 **1 秒敌人运行时间**的无敌。RT 中仍可移动，没有击退、掉书、移动动画硬直、资源惩罚或冷却延长。

无敌时重叠不会扣血、清空进度或刷新锁定。同时出现多个命中候选时按攻击 ID 排序，一步最多接受一次有效伤害。生命变成 0，立即记 `Lost`，清除危险，也阻止同一步尚未处理的最后一个字母。

## D09 — 技能怎样让玩家感到“攻击发生了”

唯一技能叫 **Pulse**。本实验免费使用，不需要能量、准度倍率、手动选目标、距离判断、弹丸飞行时间或命中概率；完成后不能再被打断。短句完成就立即扣唯一敌人 25 生命，最低为 0。可以做视觉上的飞行，但不能推迟或重复实际伤害。这是为了单独验证“打字能否像一次战斗动作”。

每个正确字母填充一个进度段；完成单词有更明显的保存提示；完成整句则同时产生：

| 反馈 | 时长 |
| --- | --- |
| 光束/命中特效 | 0.20 秒 |
| 敌人受击提示 | 0.30 秒 |
| 显示 `25` 的伤害数字 | 0.60 秒 |

不加会停止玩法的命中顿帧，也不强制镜头震动，否则奖励反馈本身会改变正在比较的危险节奏。减弱特效模式关闭强闪光和运动效果，同时保留轮廓、标签等确认信息。

从施法当步开始冷却 **0.60 秒有效战斗时间**。两种模式冷却时都恢复移动与敌人攻击，字母和重复开始命令无效。到期显示 `1 — ready` 和下一句预览，不自动开始。敌人生命变为 0 时立即显示胜利，取代冷却并取消后续攻击。输错不会意外放出一个弱化技能。

## D10 — 画面、声音与可读性

基准画面 **1280×720**；须兼容 **1920×1080** 和至少 **1024×576**，内容不能裁切。基准布局：顶部 15% 显示生命/模式/时间，中间 60% 显示平地与危险，底部 25% 显示短句与操作。

| 元素 | 基准尺寸与要求 |
| --- | --- |
| 底部完整短句 | 居中，字高至少 30 px。 |
| 角色附近/上方的当前词 | 至少 32 px，带底板，限制在屏幕内；不能与预警混成一体，也不能挡角色脚部、受击框或攻击带边缘。 |
| 辅助标签 | 至少 20 px。 |
| 文字缩放 | 100% / 125% / 150%；完整句只能在词与词之间换行。每种指定分辨率和缩放组合都要检查。 |

字体使用清楚、不花哨的字形，尤其分得清 I/l/1 与 O/0。上下两处文字必须来自同一个真实进度：完成词加勾；已输入字母用填充或下划线；下一字母用光标或轮廓；剩余字母保持普通样式。颜色只是补充，不能是唯一线索。

输错时短句不挪位置，错误字母单独短暂标记，光标只后退一次。**错误装饰/提示持续 0.35 秒，但下一字母和光标始终立即跟随最新进度**：这段时间内继续打对，也要马上向前更新，不能为了播放提示而冻结。不要把错字塞进一个可编辑句子。受击要显示与输错不同的提示，例如 `Hit: finish this word again`，持续 **0.80 秒**，但不能遮住短句。

就绪、输入中、受击锁定、冷却、暂停和结果都要一眼分得清。模式明确标为 `REAL TIME — keep dodging` 或 `COMBAT PAUSED WHILE TYPING`。教学显示“无需空格或 Enter”，可选择常驻该提示；菜单说明“长按字母不会重复输入”。结果只显示胜负/时间到、成功技能数、输错数、有效受击数、有效战斗时间和模式，不做排行榜或等级评分。

正确字母、完成词、输错、危险预警、受击、施法分别使用容易区分且不刺耳的声音。正确字母声音最多同时 4 个，超过时替换最早的，不能高速输入就无限堆积音效。逻辑处理输入后，正确/错误进度必须在**下一次画面绘制时**显示，不能再人为增加延迟；这项要求不是对键盘到屏幕整体硬件延迟的测量承诺。

预警在整个预警阶段持续可见。静音也能理解全部关键信息。战斗前可设主音量、效果音量、静音、文字缩放、减弱特效，设置跨局保留。

基准默认值：**1280×720 窗口模式、目标 60 FPS、英文界面、100% 文字大小、主音量与效果音量各 0.7、关闭静音、开启减弱特效、开启常驻操作提示**。音量范围 0–1，0 为无声；取消静音恢复此前保存的音量。30/120 FPS 用于验收，不改变打字速度；设置了目标帧率不代表实际达到。没有强制闪光、震屏、纯颜色状态或只能听见的危险提示。

若基准操作不适合某位玩家，可提供 PAUSED/练习体验并记录限制，不能宣称 v0.1 对所有人都无障碍。任意改键、单手布局、手柄和其他输入设备都要先定义独立实验条件，不能无记录地替换正式测量的操作方式。

## D12 — 容易遗漏的特殊情况

- 不支持的字符、粘贴/组合输入、忽略的标点都不推进、不罚错，也不留到之后偷偷生效。提示最多每 **2 秒有焦点的 UI 时间**出现一次。
- 快速的真实连续按键、重复字母、同一画面帧内多个按键都按顺序处理。不能靠删除相邻相同字符或限制打字速度来解决输入问题。
- 跨越暂停、开始或重试而一直按住的键，必须松开再按才算新动作。键盘断开不能留下卡住的移动。重新连接不能换句或重置生命。
- 同步发生暂停、伤害、输入时，暂停一起阻止伤害和输入。恢复确认当步没有伤害或文字输入；精确保留预警位置与阶段，再经过完整恢复倒数。
- 新键盘只有通过恢复流程后才接替断开的设备，同时清理旧设备监听与队列。双键盘协助不属于基准；设备变化要记录。
- Escape 始终是暂停，不是取消咒语。没有免费取消/刷句命令。玩家可以停止打字继续躲避，也可以通过暂停菜单结束本局。
- 短句无效/为空，或必需的 UI/输入资源缺失，就显示设置错误并阻止开局；不能自动获胜、显示看不见的替代文字，或接受空句。
- 重复完成/攻击回调用 ID 保证只生效一次。上一局延迟到达的事件不能影响重试。离开场景时取消输入监听，清理声音、视觉对象和排队事件。
- 失焦、无键盘或性能暂停时，不在后台继续模拟。**日志故障是另一回事**：游戏继续能玩，标记 `LoggingIncomplete`，并提示该局数据不能用于正式分析。
- 结果一旦生成，后续碰撞、输入、计时或一直按着的重试键都不能修改它。明确重试才创建新局；保留设置，重置玩法状态。

## D13 — 42 项验收：怎样证明规则真的做到了

## D14 — 记录什么，怎样读数据

记录只存本地、被 Git 忽略的 `artifacts/typing-combat/`，格式为 JSONL（一行一个事件）。不上传网络，不保存账号、姓名、剪贴板或任意原始按键。P01 之类只是本地参与者编号。保存短句 ID 和进度变化，不保存打出的完整原始文本。

另存一份简短的本地场次说明：条件顺序、参与者自述的打字/英语熟悉程度、辅助设置、是否同意本地笔记、观察者记录。它也不提交 Git。

| 指标 | 确切算法/含义 |
| --- | --- |
| 输入准确率 | 正确接受的字母事件数 ÷（正确接受 + 输错的受支持字母事件数）。退回后重打的正确字母仍算事件，忽略输入不算；分母为 0 写 `N/A`。 |
| 有效字母产出速度 | 已完成短句的字母总数 ÷ 有效战斗秒数；战斗秒数为 0 写 `N/A`。它不是准确率，也不是标准 WPM。 |
| 完成时间 | 第一次终局时的有效战斗时间，必须同时标注结果；保留现实时间和敌人时间。 |
| 按危险暴露时间换算的受击数 | 有效受击数 ÷ 敌人运行秒数 × 60，并同时列出敌人秒数；无暴露时间写 `N/A`。不能把 PAUSED 的每现实分钟受击数当作与 RT 同等危险下的比较。 |
| 尝试结果 | 完成；在死亡/时间到时仍未完成；主动中止。输错/受击不产生新尝试。 |
| 其他独立统计 | 第一次施法时间（没有施法则为 `N/A`）、总施法数、输错数、受击数、忽略输入数、因受击而重置单词的次数。 |

正式尝试中被指导、换设备/布局、出现性能暂停、改参数、日志不完整或意外中断，都要标记。记录仍保留，但从主要模式比较中排除并说明原因。手动/失焦暂停需报告；若玩家用它们争取思考时间，这局不能用于时间比较。

软件记录不能知道玩家是否低头看键盘，或为什么停止输入；这些需要观察和询问，不能用日志推断成事实。

<details>
<summary>实现与复核需要的日志字段（保留完整格式）</summary>

初始 `schemaVersion` 为整数 1。开局前将最终生效的配置保存成**无 BOM 的 UTF-8 JSON**：包含 D11 全部值、词库版本与所有完整短句记录、所选模式/词库，以及实际输入/辅助/显示/音量设置。对这些原始保存字节计算小写 SHA-256，作为 `configHash`；计算内容不包含校验值本身。快照以校验值为标识在本地输出目录保存一次，每局引用它。复现时读取同一文件的原字节，不能靠没有约定的重新序列化来猜测原配置。因此，即使设计仍为 0.1，模式或设置改变也会改变快照校验值。

每条事件都含：`schemaVersion`、`designVersion`、`configVersion`、`configHash`、`buildCommit`、`sessionId`、`participantLabel`、`runId`、`condition`、`bankId`、`practice`、`seq`、`tick`、`wallSeconds`、`encounterSeconds`、`enemySeconds`、`event`、`payload`。它们分别说明记录格式、设计/配置/构建版本、场次/参与者/局次、模式/词库/是否练习、顺序/逻辑步、三个时钟和事件内容。开局记录还含分辨率、显示缩放、声明的输入布局和设置。

事件种类固定为 `RunStarted`、`AttemptStarted`、`LetterAccepted`、`Typo`、`InputIgnored`、`WordCompleted`、`SpellCast`、`ThreatStarted`、`PlayerHit`、`PauseStarted`、`ResumeCompleted`、`PerformancePause`、`RunEnded`、`LoggingError`。相关事件的内容含尝试/施法/攻击 ID、短句 ID、变化前后光标、变化前后生命，以及分类原因；不需要记录具体错误字母。

由一个写入者按递增序号记录。在开局、结束和暂停时把缓冲内容写入磁盘，内存缓冲有上限。结束结果一次性完整写入，重复结束不重复写。缺少结束、序号断档或写入失败，标记数据不完整，不能编造缺失值。可以从 JSONL 导出 CSV 概要，但概要不能掩盖原始事件不完整。

## D15 — 真人试玩怎么做

第一批找 **4–6 人**，同时包括熟练盲打和较慢/需要看键盘的人；条件允许时包括没有参与实现的人。这是寻找方向的可用性测试，不是足以推出统计学结论的大样本研究。记录熟悉程度，不设置一个凭空制定的“合格打字速度”。

尽量统一构建版本、参数、键盘、显示器和音量策略。用 P0 讲解一次操作与单词保存规则，然后依次练习：只打字约 **60 秒**、只躲避约 **30 秒**、RT 综合约 **60 秒**。此时先检查是否能解释自动施法、错字回退和受击重打当前词，**在任何补充教学之前记录第一次理解检查的结果**，它才是 D16 的理解指标。若未理解，再教学并记录额外练习；后来学会也不能把第一次失败改为通过。学会后仍可参加无指导的正式局，不能把没教懂误判为不喜欢玩法。

之后每人各做一次 RT 与 PAUSED 的正式战斗，过程中不指导；每局到赢、输或 120 秒时限结束，中间可以休息。按下表轮换顺序和词库：

| 参与者位置 | 第一局 | 第二局 |
| --- | --- | --- |
| 1 | RT / A | PAUSED / B |
| 2 | PAUSED / B | RT / A |
| 3 | RT / B | PAUSED / A |
| 4 | PAUSED / A | RT / B |

更多参与者重复该轮换，不能总是先玩 RT，也不能同一种模式永远配同一词库。A/B 长度相等仍可能熟悉度不同，因此报告实际分配，不能声称已完美隔离所有变量。战斗中不调参数。不同参与者可使用不同显示辅助设置，但同一人的两局保持一致并记录。

若基准操作无法使用，可让参与者探索练习/比较模式，把可访问性限制另列，不强行当作标准试验。因不适想停可以立即停止；把不适保留为可用性发现，不归为程序错误。

每局后询问：

1. 最后一次输错/受击由什么造成，下次准备怎样改变？
2. 操作舒适度、感到的公平程度、想再玩一次的意愿，各给 1–5 分。1 表示很差/没有，5 表示很好/很强。
3. 举一个主动选择“继续输入”或“先躲避”的时刻。

两局后再问更喜欢哪种及原因。观察者记录：漏看预警、找不到下一字母、手部不适、主动暂停打字、主动要求重玩。问题不能暗示“RT 才是正确答案”。自动测试不能代替这些实际战斗，计划中的场次也不能写成已完成。

## D16 — 怎样决定继续、修改或再试一次

**第一关是功能可靠。**AT01–AT42 中所有适用项都按其要求范围取得通过证据。可复现的普通按键丢失/重复、错误施法、必要提示不可读、旧局事件污染新局、基准攻击无法躲避，都会阻止进入体验研究，先修复。缺少真实输入或画面证据属于未完成，不算通过。

**第二关是体验值得继续。**在收集数据前先固定下面的初始团队判断线，避免看完结果再挑标准。它们是临时设计标准，不是学术公认阈值。`n` 只计 RT 和 PAUSED **两局记录均可用**的人。被排除、中断或因不适退出的人与观察要单独报告，不能因不在 n 中就从报告消失。至少有 **4 位完成有效成对测试的人**，才套用这些比例；`ceil` 意为向上取整数。

| 判断项 | 初始通过线 |
| --- | --- |
| 理解规则 | 标准练习后的第一次检查、补充教学之前，至少 `ceil(0.8 × n)` 人能解释自动施法、输错退字母、受击重打当前词。 |
| 形成战斗选择 | 至少 `ceil(0.6 × n)` 人在 RT 中完成至少一次技能，并能描述一次主动选择打字/躲避。 |
| 身体操作与重玩意愿 | RT 舒适度中位数至少 3/5；至少 `ceil(0.6 × n)` 人的 RT 重玩意愿 ≥3/5。既列中位数，也列个人评分。 |

例如有 6 个有效配对，80% 项要求至少 5 人，60% 项要求至少 4 人。即使多数通过，反复出现的手部不适仍是设计问题；通过也不能证明广泛受欢迎。

如何解释结果：输入正常但规则没看懂，先改提示/教学；理解规则却找不到打字空档，下一轮只调整一个主要因素，例如敌人时间参数或句子长度；换手本身不舒服，另定义改键/慢动作实验；如果玩家持续更喜欢 PAUSED，就保留这一发现，不能强迫 RT 获胜。样本太少或结果不清楚，就再做一次有针对性的测试，不能宣布成功。

只有打字交互经过这些关口后，才进入下一轮实验，接回格挡攒能量和技能选择。那一轮必须另行明确什么时候扣次数、能否取消/退款、失败如何影响能量；完整游戏现有意向不能悄悄套入这个免费施法实验。不要通过添加 Boss 章节来掩盖打字手感的问题。

## D17 — 当前代码差在哪里，制作按什么顺序

已检查的旧基准提交为 `ae97f0e`：[ValidationGameState.cs](../Game/Assets/_Game/Validation/ValidationGameState.cs) 使用两句严格区分大小写/标点的句子、12 秒时限、开始输入时扣能量、可编辑文本和 Enter 提交。[ValidationWorld.cs](../Game/Assets/_Game/Validation/ValidationWorld.cs) 在输入时冻结角色与敌人，旧测试还专门验证这些行为。[之前的验证结果](validation-results.md) 只证明旧原型，不是本设计的结果。

后续应新建 `Game/Assets/_Game/Scenes/TypingCombatLab.unity` 以及独立 `TypingCombat` 源码/测试目录，同时保留旧场景可运行。**这些是计划路径，不是本次文档已经交付的文件。**复用固定 Unity/URP/Input System 环境、测试精灵、构建设施与测试方法；不要继承旧状态模型后，意外沿用暂停/Enter 规则。

实现至少分清以下职责。分开是为了能检查哪里出错，不要求玩家理解内部结构。

| 部分 | 负责什么，以及不能做什么 |
| --- | --- |
| 输入转换 | 处理真实按键、文字/控制键分流、时间戳、布局检查、重复过滤、设备连接；只发事件，不改生命或文字进度。 |
| 打字规则 | 保存固定短句与词/字母位置，判断正确、输错、保存和完成；不依赖 UI。 |
| 战斗统筹 | 管理 D06–D09 的状态、固定步骤、优先级、危险、位置、生命，确保效果只发生一次。 |
| 画面表现 | 根据只读状态显示两处文字、预警、生命、反馈、菜单和辅助设置；不决定字母是否正确。 |
| 本地记录 | 有序事件、数据质量标记和每局摘要；写入失败不能改变战斗规则。 |

制作顺序及每步的退出条件：

1. **先做真实输入的小实验。**一个可见的纯打字场景，结合真实键盘与输入处理测试，验证长按、重复字母、快速同批输入、大小写、快捷键、不支持输入。若无法可靠关联输入来源和按下次数，先解决，不能用限速掩盖。
2. **打通纯打字循环。**实现单词保存、错一个退一个、自动且只释放一次 Pulse、冷却。先验证状态例子，再加威胁。
